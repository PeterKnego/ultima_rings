# Bake-off: ultima_rings vs ecosystem channels

**Date:** 2026-08-06  
**Branch:** `feat/v1`  
**Hardware:** 4-core single box, ~4 idle cores at run time, no parallel builds during measurement

## Methodology

Criterion benchmark (`benches/throughput.rs`) measuring sustained throughput under no backpressure (`BusySpin` wait strategy only), comparing against ecosystem crates' own harness shape:

- **SPSC**: `crossbeam-channel`, `rtrb`, `kanal`, `flume`
- **MPSC** (2 producers, 1024 capacity, 4-core box): `crossbeam-channel`, `flume`, `kanal` (rtrb is SPSC-only)

Criterion samples were collected in a normal (non-quick) run; smoke (`--quick`) numbers were noise-stable with the full run for all cells except `bakeoff_spsc/crossbeam-channel` (system noise on a shared box, not a code change).

## Results

| Group | Competitor | Melem/s (mid) | Melem/s (range) |
|---|---|---:|---|
| SPSC | **ultima_rings BusySpin (pipelined)** | **620.1** | 610.9 – 629.2 |
| SPSC | rtrb | 626.5 | 617.2 – 635.8 |
| SPSC | crossbeam-channel | 39.9 | 38.5 – 41.3 |
| SPSC | kanal | 20.7 | 19.7 – 21.7 |
| SPSC | flume | 10.9 | 10.8 – 11.0 |
| MPSC (2 producers) | crossbeam-channel | 71.0 | 70.1 – 71.9 |
| MPSC (2 producers) | **ultima_rings BusySpin** | **29.9** | 29.6 – 30.1 |
| MPSC (2 producers) | flume | 7.7 | 7.6 – 7.7 |
| MPSC (2 producers) | kanal | 5.3 | 5.1 – 5.5 |

**SPSC:** ultima_rings leads crossbeam-channel by ~**15.5×** and lands at parity with rtrb (also a minimal-overhead, wait-strategy-free lock-free SPSC ring).

**MPSC:** ultima_rings trails crossbeam-channel at ~**0.42×** its throughput on this 2-producer/4-core box. This is an accepted, documented v1 trade-off — the bounded-CAS claim buys correctness properties `fetch_add` cannot, at the cost of a CAS-retry loop; a batched claim (reserving a contiguous run of sequences per CAS) is the identified v2 optimization lever. rtrb's single-pop throughput (626 Melem/s SPSC) vs our batched-`drain` result (620.1) shows the batching is not the headline's source.

## Implementation notes

**API wire protocol:** SPSC's `tail` Release/`head` Acquire pair and MPSC's `avail[slot] = seq / cap` round-encoding are byte-equivalent to the `hi-perf-cmp` bench cells that produced the AWS numbers in the README, so these numbers are directionally representative of the crate's own cores (though not a re-run against real AWS hardware).

**Dev-dependencies:** `crossbeam-channel = "0.5.16"`, `flume = "0.11.1"`, `kanal = "0.1.1"`, `rtrb = "0.3.4"` — all added to `[dev-dependencies]` only, never production dependencies.

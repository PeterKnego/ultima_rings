# Bake-off re-run: ultima_rings vs ecosystem channels

**Date:** 2026-08-09
**Hardware:** 4-core Linux VM, 15 GiB RAM, no swap
**Box state:** verified by `vmstat` before and between runs — 86–91% idle, 0–1
runnable, steal 0. (Load average is not used here: it has read above 2.0 on this
machine while `vmstat` showed 90% idle.)
**Method:** built to completion first; three full runs of every cell in one
session; criterion mean per cell, reported as median-of-three with the full range.

Supersedes `2026-08-06-bakeoff.md` as the current measurement. That file is kept
for history — but see the first finding below for why its numbers cannot be
compared against these directly.

## Finding 1: this box is ~20% slower than it was on 2026-08-06, on unchanged code

`src/spsc.rs` has not been modified since the v1 bake-off. It measures 466–523
Melem/s here against v1's 620.1. `rtrb` — a third-party crate, also unchanged —
fell in lockstep, 513–576 against v1's 626.5.

Two independent, unmodified codebases dropping by the same proportion is a
property of the machine, not of either crate. **Absolute figures from this
session and from 2026-08-06 are therefore not comparable**, and no delta computed
across the two files means anything.

What remains valid is **ratios within a single session**, which is how the results
below are framed.

## Finding 2: the "parity with rtrb" claim does not reproduce

v1 recorded SPSC at 620.1 against rtrb's 626.5 — a 0.99x ratio, reported as
parity. This session measures 0.86x (480.65 vs 561.64), and rtrb led in all three
runs individually (0.91x, 0.91x, 0.86x), so this is not an artifact of pairing
medians.

`src/spsc.rs` is unchanged between the two measurements, so this is not a
regression in this crate. Either v1's pairing was favourable noise, or the two
crates respond differently to whatever changed about the box. **Not diagnosed
here.** The README's parity claim has been softened to match what reproduces.

## Finding 3: kanal's numbers are not stable enough to report as a point estimate

kanal's SPSC cell spans 4.77 – 10.93 Melem/s across three runs — a **129% spread**,
where every other SPSC cell sits under 20%. Its MPSC cell spans 5.42 – 9.12 (68%).
No other competitor behaves this way in this session.

Its median is reported above for completeness, but a median of three runs is not a
meaningful summary of a distribution that wide, and the table flags it rather than
presenting it as comparable to the others. Diagnosing why kanal is bimodal on this
box was not attempted.

## What this says about the MPSC work

This crate's MPSC measures 0.58x crossbeam here, against v1's 0.42x. **That
comparison is not evidence of improvement**, for exactly the reason Finding 1
gives: the two figures come from sessions whose absolute scale differs by ~20%.

The evidence for the colocation change is the A-B-A blocked layout probe in
`2026-08-09-colocated-slot.md` (+15.45% / +14.59% / +11.93% across three
configurations, measured within one session against an interleaved baseline), not
this table. What this table adds is that the improvement is visible in the
head-to-head framing too, and that it did not come at a cost anywhere else.

One directional observation, offered as such and not quantified: the MPSC cell
rose while unchanged SPSC code on the same box fell ~20%. That is consistent with
a real MPSC gain, but the cross-session scale difference means no number should be
derived from it.

## Ratio denominators

crossbeam's MPSC figure is stable *within* this session (59.44 – 60.62, 2.0%
spread) but sits below the 71.25 Melem/s measured when it was run in isolation
(`2026-08-07-sharded-mpsc.md`, "Follow-up"). That is the documented behaviour:
crossbeam yields under contention where this crate spins, so its throughput tracks
how much else is running — and a full bake-off run is a busier context than an
isolated cell.

Against crossbeam's best-ever observed figure on this box (71.25), the same-session
medians give: `sharded` 4.45x, `mpsc` 0.49x, `Park` 0.20x. Those are the
least-favourable denominators available for this crate, and are quoted alongside
the same-session ratios rather than in place of them.

## Reproducing

```
cargo bench --all-features --bench throughput -- \
  'spsc/busy_spin_pipelined|bakeoff_spsc|mpsc/busy_spin_2_producers|bakeoff_mpsc|bakeoff_park_mpsc|bakeoff_sharded_mpsc'
```

Check `vmstat 2 3` first (want 85%+ idle, 0 runnable) and build to completion
before measuring. One full pass takes about 2m20s.
